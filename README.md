# 活动账本

和朋友一起 AA 记账的小应用：以「活动」为单位分账，自动算出**最少转账方案**。

界面为中文、移动端优先。

## 特点

- **无需注册**：用链接就能加入活动，选择或新建一个身份即可；身份可以改名、上传头像（服务端自动裁成 100×100 WebP）。身份无密码，假定大家都是善意的；这也意味着身份可以被冒用，请不要与不信任的人共用链接。
- **活动制账本**：每个活动有唯一 ID，链接即钥匙。
- **付款灵活**：每笔付款有标题、可选时间和备注；可以有多个付款人（各自支付不同金额），**总额 = 所有付款人支付金额之和**；参与人可选择**均分**或**自定义分摊**。
- **自助参与 + 管理权限**：任何人都可以把自己加入某笔付款（作为付款人或参与人）；修改分摊、调整角色、移除他人由付款创建者和活动管理员负责，本人不能自行退出。
- **结算前全员表态**：每个人对每笔付款都必须明确回应——参与的人确认金额，没参与的人显式声明「我没参与」。**只要有人没表态（未知状态），就不会计算转账方案**，并会列出未回应的人。
- **关闭活动后才出结算方案**：转账方案由管理员确认关闭活动后生成；有成员未回应时无法正常关闭，可强制关闭（未确认的成员按「未参与」处理）。
- **管理员密码**：活动创建者可设置密码，用于保护回滚等高级操作。

## 快速开始

要求：Node.js ≥ 22（使用内置 `node:sqlite`）、pnpm。

```bash
pnpm install
pnpm dev        # 前端 http://localhost:5173，API http://localhost:3000
```

生产构建与运行（单进程同时提供前端与 API）：

```bash
pnpm build
pnpm start      # http://localhost:3000
```

环境变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 服务端口 |
| `LEDGER_DB` | `data/ledger.db` | SQLite 数据文件路径（目录会自动创建） |

> 上线时建议把数据文件挂载到持久化磁盘，并在前面放一层 HTTPS。

## 记账模型

- **活动 (activity)**：账本的单位，包含若干身份与付款。
- **身份 (identity)**：活动内的成员，无密码；有名字和可选头像（100×100 WebP，存储在事件流中，随回滚一起回退）。
- **付款 (payment)**：标题、可选时间/备注、分摊方式（均分 / 自定义）。
  - **总额**：等于所有付款人支付金额之和，无需单独填写。
  - **付款人 (payer)**：一个或多个，各自可支付不同金额。
  - **参与人 (participant)**：分摊这笔付款的人，每人有各自的确认状态。
- **每人对每笔付款的状态**：
  - **付款人 / 参与人**（已确认）：确认过自己的金额或份额。
  - **待确认**：被登记进付款，但金额/份额还没确认。
  - **未参与**：显式声明过「我没参与」。
  - **未知**：什么也没做——默认状态，会阻塞结算。
- **待完善 (incomplete)**：自定义分摊的金额合计与付款总额不一致时，该笔付款不计入结算。
- **结算**：`余额 = 支付金额 - 分摊金额`；管理员关闭活动后，用贪心算法（最大债务人 ↔ 最大债权人）生成不超过 `n-1` 笔的转账方案。
  - 正常关闭：要求所有成员都已回应（没有「未知」或「待确认」）。
  - 强制关闭：仍有未回应成员时可用；未确认的付款/参与登记会被移除，相关成员标记为「未参与」，然后生成方案。
  - 关闭后账目锁定；如需修改，管理员可在「记录」中回滚关闭操作。

## 权限规则

| 操作 | 谁可以 |
| --- | --- |
| 加入活动（新建身份） | 任何拿到链接的人 |
| 修改自己的名字 / 头像 | 本人（只能改自己） |
| 新建付款（创建者必须是付款人） | 活动内任意身份 |
| 把自己登记为付款人、修改自己的付款金额 | 本人 |
| 把自己加入为参与人 | 本人 |
| 确认自己的参与 | 本人 |
| 声明「我没参与」（仅限未被登记进该付款时） | 本人 |
| 切换到管理员（创建者）身份 | 需要验证管理员密码（活动已设置密码时） |
| 修改分摊金额、调整他人的付款人/参与人身份、移除他人 | 付款创建者，或已解锁密码的活动管理员 |
| 退出付款（包括退出自己） | 付款创建者，或已解锁密码的活动管理员 |
| 编辑 / 作废付款 | 付款创建者，或已解锁密码的活动管理员 |
| 关闭活动 | 活动创建者 + 管理员密码（有未确认时只能强制关闭） |
| 回滚、修改活动信息、设置密码 | 活动创建者 + 管理员密码 |

说明：

- **付款创建者必须始终是付款人**：创建时强制，且任何人都不能把创建者移出付款人列表。
- **本人不能退出或修改自己的参与**（包括分摊金额与付款人/参与人身份）。登记有误时，需要联系付款创建者或活动管理员处理。
- 自定义分摊模式下，他人的分摊金额由付款创建者设置；自助加入的人会先处于「待设置」状态，付款在金额补齐并确认前不计入结算。

## 回滚是怎么工作的

所有变更都是追加式事件（`events` 表）。读取时按顺序折叠出当前状态；回滚事件把「当前有效时间线」截断到目标事件，之后的变更变为「已撤销」（保留在历史中，不会真正删除）。已被撤销的事件不会因为再次回滚而恢复。

管理员密码单独存放在 `activities.admin_password_hash`（scrypt 加盐哈希），不属于事件流，因此回滚不会影响密码。

## 已知取舍

- 无账号体系，身份可被冒用，仅适合善意场景。
- 结算使用贪心近似（保证 ≤ n-1 笔且一定能结清），并非严格数学最优。
- 金额以「分」为单位存储，均分产生的余数按参与顺序分配。
- 事件全量重放，活动规模很大时需要引入快照（见 `docs/TODO.md`）。
